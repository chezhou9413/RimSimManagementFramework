# 餐厅会话与子订单闭环

一次 `RestaurantDiningSession` 绑定一个框架动作、一名顾客及一个餐位。每次成功交谈产生一张独立的 `RestaurantOrder`，拥有自己的库存预留、时间、价格、实物、成本与结算明细。首次占座时的占位订单只承载等待接单，不提前确定商品。

1. 顾客入座，创建本人桌面托盘，开始首次接单等待。
2. 服务员认领唯一待接单请求，交谈 120 Tick。完成时重查预算、偏好、需求、实物及完整路线，冻结商品和数量，并预留真实 Thing。
3. 厨房订单进入 `WaitingCook → Cooking → ChefBringingToPass → ReadyToDeliver`。厨师先搬冰箱食材，再搬绑定后厨食材，核实实际投料后生成一次成品。
4. 柜中现货直接进入 `ReadyToDeliver`。服务员从冻结的来源柜提取预留商品，保持不同品质、成分与腐坏进度的独立堆叠。
5. `Delivering` 在顾客旁持续 90 Tick，全部商品转入该顾客托盘后进入 `Dining`。
6. 顾客按送达顺序从本人托盘取物。Consume 执行原版咀嚼和进食；TakeAway 转入本人库存，并在框架记录实物引用。
7. 等待和进食不阻止追加：一次只有一个接单请求，可同时存在多张制作或配送订单。默认最多 3 次，间隔 1200 Tick，已确认金额和剩余营养从后续选择中扣除。
8. 停止追加且全部子订单已处理后，按实际接受数量汇总账单，完成框架动作，释放餐位并进入 `AwaitingCheckout`。
9. 收银成功按动作及子订单标识核对明细，完成会话与已结算子订单。收银失败不登记收入，回收仍存在的未付款带走商品，不重建已吃掉的东西。

接待和上菜分别使用单店等待期限，交谈重试与追加不会延长既有订单期限。服务超时停止追加，取消未交付订单；已收到可用商品继续吃喝或接受。失败订单保留实际消耗成本，未收到商品不收费。

制作中断释放未消耗食材的业务预留；已产生成品只恢复运输。员工携带、出餐台、桌面托盘与顾客库存保存直接实物引用，各持有者负责深度存档。临时落地的订单商品禁止普通取用，恢复或终止清理标记。顾客从入座到吃完没有地面取餐步骤。

批量账单入口 `QueueActionOrderCharges` 使用动作订单与子订单双层标识；同一条明细重试不重复收费，改变已登记金额会明确报错。应付款、成本和付款结果分开保存，实际收入仍仅由框架收银提交。
