# 家具、库存与商品配置

## 建店与补货

1. 在框架经营分类建造餐桌和座位、接待与出餐台、收银台及所需货柜，划入同店商店区域。需要烹饪时配备兼容灶台和厨师。
2. 在同地图创建原版储存区放置后厨货源；单店餐厅参数中勾选需要绑定的区域，回到父窗口统一保存。多个店铺可以共享区域，实物预留按地图统一协调。
3. 打开冰箱或商品柜管理，勾选允许物品，设置逐项目标、补货阈值并保存。全部品种的目标总和不能超过共享容量；没有启用配置的品种不自动补货。
4. 分配框架补货岗位。自动补货在达到阈值时进入任务队列；“按已保存目标补货”主动提交补至目标请求。途中数量参与容量计算，人员必须实际从绑定区域搬运。
5. 商品柜另外设置售价、上架状态、份数和交付方式。现场吃喝只能用于原版可进食商品；带走商品保留在顾客库存中，最后统一收银。

| RSR_DiningTableSquare | 1×1 | 原版进食桌面 |

冰箱供电只暂停 CompRottable 更新，不清空腐坏进度，也不暂停其他组件。断电恢复按环境温度腐坏；普通商品柜没有冷藏作用。冰箱和商品柜均不参与顾客自取零售池。

厨师按“本店可达冰箱 → 已绑定后厨区域”查找原料，同级按距离排序，允许两类来源组合满足一单。菜单预览、接单预留和实际搬运使用相同查询，不扫描整个店内地面作为货源。区域删除、柜体拆除和筛选变更会使尚未取出的相关预留失效；已搬至灶台的食材仍属于制作任务。

## XML 扩展

`RestaurantProductDef` 支持：

- `things`：明确 ThingDef 列表。
- `categories`：ThingCategoryDef 分类及其子类。
- `excludedThings`：优先排除的物品。
- `defaultPrice`：基础单价，-1 表示使用市价倍率默认值。
- `defaultCount`、`selectionWeight`：每次接单份数和选择权重。
- `deliveryMode`：Consume 或 TakeAway。
- `ingredientsOnly`：用于冰箱食材范围，不要求现场进食。

在建筑的 `RestaurantStorageExtension.products` 中引用商品 Def。游戏内允许列表可以进一步缩小范围，逐柜售价、份数和上架状态独立保存。同一种物品在多个柜内会形成保留来源与价格的不同菜单项；成交后冻结本次来源与单价。

原版示例位于 `1.6/Defs/RestaurantProducts.xml`，包含啤酒、成品食品与带走商品。[MayRequire 示例](Examples/RestaurantProductMayRequire.xml) 放在文档目录，不自动加载；接入其他模组时替换示例包 ID 和 ThingDef，并在建筑配置中引用。非法配置通过具体 Def 名和原因报告。

## 多次点单与界面

单店参数可设置接单上限 1～5 次（含首次），默认 3 次；追加间隔默认 1200 Tick。追加同时考虑剩余预算、偏好和未吃完商品的预期营养，同一顾客不会并发两个接单请求。每次仍只选一个菜单项，保留其份数设置。

总览按顾客会话汇总，展开查看每张子订单的轮次、来源、员工、阶段和阻塞原因。统计使用完整会话集合，搜索分页只改变列表。订单金额是报价，待付款是实际接受的应付金额，已付款以收银回调为准。

菜单及参数编辑属于父窗口草稿，切页保留、关闭丢弃，父窗口保存才应用。货柜窗口独立保存其库存与销售草稿；补货按钮使用已经保存的目标。建议先保存目标，再主动补货。
