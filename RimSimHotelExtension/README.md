# RimSimHotelExtension

RimWorld 1.7 / .NET 10 旅馆与温泉扩展，依赖 `RimSimManagementFramework`。餐厅是可选消费场所，旅馆不引用餐厅程序集；经营逻辑通过框架通用消费接口接入。

## 开始经营

1. 划定商店区域，建造一个主服务台，安排接待员及营业时间。
2. 在该区域内建造床位。所有使用原版床逻辑的床均可登记，包括旅馆专用床、普通床和其他模组的床。选中床，点击或右键用途按钮，选择“旅客专属”即可立即登记；没有原版用途按钮的床会补上同样的入口。也可打开“商店管理 → 服务管理 → 客房”，通过床位行的“编辑”登记；子窗口确认后，再点击主窗口“保存全部设置”。点击“旅馆设置”调整入睡时间、起床时间和单人／双人床报价。未登记的床不接待旅馆顾客，已有合同保留成交价。
3. 准备可购买的食物、其他商品或付费服务。住客保留真实饥饿和休息需求，会进食已购买的食物并回自己的床睡觉。
4. 建造并供电取钱机，让住客把有限旅行账户资金转到钱包。机器只收手续费，不生成本金。
5. 温泉需要供电，并在同一商店区域内配置衣物暂存柜；每名使用者占一个柜。木池四人、石池六人，两种均占 6×4 格。

作息按每家旅馆单独保存，默认当地时间 22:00 入睡、07:00 起床，支持跨午夜或日间睡觉。保存后对当前住客生效。睡觉时段不再安排闲逛和新消费；已经消费的顾客完成当前服务、结清账单后回自己的床，即使精力充满也睡到设定的起床时间。退房和紧急离店仍可结束睡眠。日间精力不足时仍可自行补觉。

登记出租床位所在的封闭客房只允许本房间住客和同行者进入，空房也不作为闲逛空间。普通购物、用餐、温泉顾客以及其他房间住客不能在里面休闲、排队或抄近路；敞开的房门同样受限制。同一房间内已分配床位的住客可以共用该房间，员工和殖民者照常通行。入住和换房检查仅临时核实候选客房的通路，不授予实际移动权限。权限在床位登记、合同或建筑布局变化时更新并清除旧的可达性缓存；房间变更时已在里面的顾客可以离开。露天床位不把整片地图划为私人客房。

经商管理中有旅馆总览；店铺管理的“服务管理”内按设施显示客房、住客、温泉和取钱机子页。首页使用紧凑摘要和可排序列表；房价、票价、手续费与出租登记通过“编辑”或设置按钮打开二级窗口，合同、消费流水、衣柜及取款记录按需查看。子窗口确认只更新草稿，取消不保留该次编辑；主窗口“保存全部设置”才生效，取消或关闭主窗口会丢弃整次草稿。定位立即执行，已成交合同和温泉会话保留原价。

快捷菜单和客房页面使用同一套登记检查：床必须已建成且属于玩家，划入商店区域，同店建有旅馆服务台；不能处于医疗、囚犯、奴隶用途，也不能正在燃烧、已分配床主或有人躺卧。失败时保持原状态并提示处理方式；多选快捷登记会先核对全部床，不会只登记其中一部分。接待时间和暂时无人值班不影响登记。床型、体型和种族适配仍在实际入住时核对。

旅客专属床由住宿合同分配，殖民者不会自动占用。切回“殖民者专属”或“普通用途”可立即取消出租；切换医疗、囚犯或奴隶用途也会取消出租。床已有预订或住客时拒绝更改，并提示等待退房。

## 调试商圈

启用开发者模式，打开调试动作菜单，在 `SimHotel` 下选择 **生成旅馆商圈 / Create hotel district (37×31 / 54×31)**，然后点击一块已探索的空地中心。

生成器会创建 4 间客房（2 张单人床、2 张双人床并登记出租）、服务台、取钱机、木制和石制温泉、10 个衣物暂存柜，以及独立的食品店和服装店。商品柜内放入真实的生存餐、T 恤、裤子和防寒服；3 名新员工已分配岗位、设置工作优先级，并有独立宿舍与口粮。房间带屋顶、照明、供暖和连通的独立电源。

未启用餐厅扩展时，商圈占地为 37×31；启用后自动扩展至 54×31，在东侧追加一间独立营业的餐厅。餐厅复用餐厅扩展的完整调试模板，包含菜单、真实食材、已加燃料的炉灶及发电机、商品柜、餐桌座位，以及收银员、厨师、服务员和补货员。生成后检查实际营业条件，失败时明确报告原因。

整块用地必须无区划、无建筑或物品且能承重。生成前先检查用地和所需定义，遇到冲突会报告位置；通过后清理植物、污物并铺地。餐厅仅在已启用时通过可选调试入口调用，不增加必需依赖；未启用时仍可独立生成旅馆商圈。不修改客源设置、游戏时间或全局电力。生成后的顾客按正常规则到访，旅馆入住在 08:00～24:00 办理，员工保留正常生活与睡眠。需要立即刷客时可使用框架已有的 `SimShop → 强制刷新顾客（当前地图）`。

## 住宿与消费

入住意向为 1～7 晚，入住动作选择权重为 3，仍按最低住宿房费、餐费及离店储备检查预算。可用双人床允许同行两人共用整床合同，两人分别保管钱包、分别活动，同进同退。双人床单人独占仍收整床价格。

住客的住宿记录独立于短暂商店访问。任何接入框架商品、付费服务或 `CustomerAction` 的店铺，都通过统一可用性查询参与寻店和消费。查询不创建订单、不占座、不扣库存；进入商店后继续执行原扩展任务、订单、结账与购后服务。动态动作由原 Worker 决定成交价。

住客可以反复访问同一家店，消费完成后返回住宿日程。有限资金、兴趣、价格接受度、营业状态和可达性仍影响选择。没有餐厅时，普通食品商店可以提供真实食物；有餐厅时，其现有动作自然参与消费，无需“旅馆兼容代码”。

消费间隙，住客会在自己的客房和旅馆公共空间散步、停留，或使用桌边空座休息。休闲会避开其他卧室、前台服务格和排队位置，不取用未购买的食物及商品；短暂活动结束后继续检查基本需求和住宿安排。没有可用空间时才原地等待。

房费预付款保存在合同中，每晚开始才转为服务台现金及营业收入。提前退房退还未开始的整晚。停止接待不取消已有合同；前台无人时退房等待到期后仍会释放床位。温泉顾客先预留池位和衣柜，再到同一商店的旅馆服务台排队购票，接待员在岗并完成付款后才存衣入池。无人值班时等待，购票超时则取消并释放预约；票款在实际开始泡汤时转为服务台现金及营业收入，入池前取消原额退款。柜子保管真实衣物实例，中断归还，拆除或损毁释放物品。

服务台的入住、续住、退房及温泉购票需求均可触发临时补位，不必等待指定接待员。前台暂时无人时允许顾客先建立待接待合同并等待，实际接待和入住扣款仍需接待员到岗。接待员正在为其他顾客办理业务时，同台排队顾客的耐心暂停消耗，入住与退房的外层超时也扣除这些服务时间；仅站岗而没有实际办理业务不暂停计时。

住宿接待、温泉购票和普通收银共用前台队列，只有队首能够预约服务格。等待位置会提前保留，拥挤时不会反复随机换位；没有空位时保留队号等待。住宿接待显示等待读条和实际服务进度，员工离岗时服务进度暂停，结束或中断后清理读条。

## 初始数值

| 项目 | 默认值 |
|---|---|
| 单人／双人整床 | 55／90 银每晚 |
| 初次晚数及权重 | 1～7 晚；30、30、25、20、12、8、5 |
| 接待／开始计费／退房 | 08:00～24:00／18:00／10:00 |
| 同行申请 | 有空双人床且两个人数名额时 25% |
| 续住 | 满意度至少 65，资金足够续 1～2 晚，总计最多 10 晚 |
| 木温泉 | 30 银，3000 Tick，休闲 +0.35，满意度 +3 |
| 石温泉 | 45 银，3750 Tick，休闲 +0.45，满意度 +5 |
| 泡汤限制 | 每日一次，至少间隔 30000 Tick；排队耐心 2500 Tick |
| 取款 | 2 银手续费，450 Tick，每人每日最多 250 银，目标钱包 300 银 |
| 接待操作 | 入住 600 Tick，续住／退房 300 Tick；等待期限 5000 Tick |
| 新旅馆旅客总旅行资金 | 400～1400 银，只生成一次 |
| 预算保留 | 普通饮食按每人每日 70 银估算，另留 20 银余量 |

既有顾客使用当前实际剩余预算，不额外创建本金。初始钱包为房费预付款加 150 银，上限为总资金，其余进入旅行账户。可选消费按剩余资金与住宿天数分配。

数值集中在 `1.7/Defs/HotelTuning.xml`；客源预算和营业曲线使用框架 `HotelCustomers.xml`。房费、温泉票价等 UI 参数是每家商店独立设置。建筑维护来自电力、清洁、修理和员工劳动，没有额外的每日虚构扣费。

资金基线：900 银住四晚，房费 220、食物 280、木温泉两次 60、其他购物 160、手续费 4，共消费 724，余 176。食物以每份 35 银为估算参照；取款本金不算消费或收入。这是初始分析基线，尚未经过游戏实测。

## 素材与构建

从用户提供的 `旅馆-温泉组.zip` 原样导入 39 张 PNG：单人床与双人床各 3 个方向及 3 张材质遮罩，柜体 3 个方向，两种温泉分别包含池底、水面、外框和合成预览各 3 个方向。正面、背面、侧面映射到 south、north、east；west 使用原版镜像。温泉使用静态分层绘制，无自定义 Shader。服务台和取钱机复用框架收银设施贴图。

温泉放置和选中时显示占地及固定池位，四向坐标以原版实际占地为准，并按石池的岸边和西向镜像安排座位。施工需要重型地基，池内不能与建筑、蓝图或建造框架叠放；经营区域和衣柜可在施工后配置。

池底、半透明水面和池沿分别使用原版绘制层，池沿不会覆盖人物头部。泡汤时启用原版游泳绘制，两排顾客相向而坐；离池或中断恢复正常绘制，读档后依据持久会话恢复。营业时有少量原版水汽。合成贴图用于施工轮廓预览，建成后的水面使用真实 Alpha 混合。

实现参考了 [Standalone Hot Spring](https://steamcommunity.com/workshop/filedetails/?id=2205980094) 的占地内固定池位，以及 [Dubs Bad Hygiene](https://steamcommunity.com/sharedfiles/filedetails/?id=836308268) 的池底／透明水层和 1.7 游泳状态处理。保留本扩展的贴图与独立业务逻辑，不依赖这些 Mod。

执行本目录 `build.bat` 或仓库根目录 `compile_modSelf.bat` 编译三个工程；`deploy_modSelf.bat` 使用统一部署入口。编译不启动游戏。此扩展保存合同、个人账户、预付款、床主、温泉会话、衣柜实际物品及近期资金记录，不提供旧格式迁移。

后续游戏验收包括同行固定睡位与独立消费、三类店铺自动发现、反复访问、零余额与续住退款、各活动状态存读档、设施失效与袭击中断，以及中文长名称和 UI 缩放。
