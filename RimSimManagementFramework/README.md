# RimSimManagementFramework

本目录是模拟经营框架 Mod 根目录，包含 `About`、`Content`、`LoadFolders.xml`、`1.6` 与 `1.7`，同时支持 RimWorld 1.6 和 1.7。餐厅扩展位于同级目录 [RimSimRestaurantExtension](../RimSimRestaurantExtension/README.md)。

Git 仓库根目录为上一级 `RimSimFramework`。两个 Mod 共用编译和部署脚本，具体目录与参数见 [仓库说明](../README.md)。

运行本目录的 `compile_modSelf.bat` 会依次编译框架和餐厅。运行 `deploy_modSelf.bat` 或 `deploy_modSelf.ps1` 会先编译，再将两个 Mod 分别安装到 Steam 游戏的 `Mods` 目录。

框架唯一源码、.NET 10 工程与 `SimManagementLib.slnx` 位于根目录 `Source/SimManagementLib`，解决方案包含框架和同级餐厅工程。后续只维护 1.7，默认构建 1.7 Release，程序集位于 `1.7/Assemblies`。1.7 资源独立加载；1.6 的程序集和资源冻结，不再更新或重新编译。

在“统一 LLM 设置 → 经营顾问”开启功能后，“经商管理”显示独立顾问子页。支持连续聊天、经营总结、建议和停业诊断，可导入 TXT / JSON 人格、经营期望及 PNG / JPG 头像。顾问可沿用统一接口并指定另一模型，也可单独配置供应商、地址、密钥和模型；顾客评价继续使用自己的原有配置。

顾问按需查询店铺、财务、库存、人员、顾客、评价、服务与备餐订单、商品分类、建造定义和地图格子。`commands` 提供可调用的原版指令与颜色目录，`colonists` 提供殖民者技能、禁用工作、当前任务和优先级，`work_types` 提供工作类型。地图查询包含基础地形、桥梁/地基、正在建造的定义和已有工作指令。当前框架与已加载餐厅扩展的源码和 Defs 随 DLL 打包，可检索并读取带行号的片段；不会访问任意磁盘文件。查询过程显示空间、对象、条件及结果，机制分析可以引用源码依据。动态指标可能使用游戏缓存，账单明细受既有保留数量限制。

顾问可提出营业日程、岗位分配、工作优先级、货柜分类和商品配置、专业衣架上架与定价、店铺命名、区域划定及建造方案。默认手动审批，方案直接显示在聊天页底部，可核对目标、前后值、放置方式和材料需求，并点击“批准执行”或“拒绝方案”；“查看详情”可打开完整弹窗。聊天中的“同意”或回车不会直接授权。在“LLM 设置 → 经营顾问”开启“全自动审批并执行顾问方案”后，通过校验的方案直接执行，聊天和过程记录保留方案，状态栏显示当前目标与进度。助手不能修改审批开关；关闭全自动会停止剩余自动执行步骤，已完成步骤保留。每批最多 32 个操作，每个员工或货柜每批一个操作；存在依赖的清理、建造、全局工作模式与人员优先级等分批提交。

普通模式放置施工蓝图，需要研究、工人和材料；上帝模式使用原版即时建造，无需科技、材料和施工。单个 `blueprint` 支持多格家具；`build_rect` 支持单格墙体、地板及桥梁的一行、一列或矩形铺设，每边最大 50 格，每批总面积和实际目标不超过 2500，更大任务拆批。已有相同成品、蓝图和框架跳过，其他冲突反馈给顾问；地板和建筑能否共存按原版检查。批量执行每帧最多推进 8 个目标，并在耗时达到 8 毫秒后让出当前帧；单个原版调用仍需完整执行。屋顶可通过原版建屋顶/拆屋顶指令安排。模式变化使旧方案失效，重新生成方案后按当前审批设置处理。

`order` 通过原版 Designator 下达割除、伐木、收获、采矿/整条矿脉、搬运、拆除、卸载、取消、允许/禁止、占领、狩猎、驯服、屠宰、放生、剥衣、开启、挖树、取出燃料、平整、移除地板/桥梁、油漆/去漆、规划、屋顶、家园、除雪和清污染区等指令；目录中显示 DLC 与规则可用性。可指定精确对象或矩形，只处理原版允许的目标并记录跳过数量。整条矿脉操作只接受单个矿石编号，作用范围可能超出矩形，预览会说明。顾问可以调整殖民者工作优先级；需要 1/2/4 级时先通过独立的 `work_mode` 操作开启原版手动优先级。下达指令不代表工作已完成，殖民者仍受工作资格、材料、区域、可达性、征召和当前状态约束；上帝模式沿用原版即时行为。修改营业日程不改变世界日期。

占位冲突、参数错误、回复格式错误、回复截断和暂时网络故障会反馈给顾问，保留原任务及部分执行结果，由顾问重新查询并调整方案。重复错误逐渐延长等待，不原样重放失败的殖民地操作；重试计入已有单任务轮数额度，0 仍为无限。身份认证、模型配置或协议不匹配等需玩家修正的错误会停止并说明原因。界面显示等待模型的秒数、重试倒计时及批量目标进度。普通模式需要等待殖民者清理或施工时，顾问可用 `wait_work` 在本地观察指定区域，不持续调用模型消耗 token。工作清空或经过 5000 游戏刻后返回实际剩余数量，顾问再查询现状继续施工或诊断阻碍；暂停游戏也暂停等待，关闭窗口或停止任务会取消等待。

顾问输入区提供“标记区块”：在地图上拖动框选矩形，或单击标记一格，完成后自动回到顾问页。附件显示地图、起止坐标和大小，可移除或重新框选；发送问题或快捷问题时一并发给助手，提交成功后移除附件。右键或 Esc 取消框选并保留原附件与草稿。助手按精确范围查询和规划，大区块按不超过 16×16 的子块分页读取；标记本身不修改地图，也不代替操作审批。

顾问任务默认不限轮数，不再因固定 8 轮或 18 万上下文字符中止。在“LLM 设置 → 经营顾问”可配置单次任务的模型请求轮数上限，0 表示无限；每次发送玩家消息重新计数，查询和审批后继续分析都计入同一任务，可随时停止。接口自身的上下文和频率限制仍由供应商决定。

顾问支持 OpenAI 兼容 Chat Completions 接口及 Anthropic 原生 Messages 接口，可填写对应服务的模型标识；兼容服务使用自定义 Base URL。OpenAI 兼容接口默认启用 JSON 输出约束，若模型或网关拒绝 `response_format` / `json_object`，可在“LLM 设置 → 经营顾问”关闭“使用接口 JSON 输出约束”，保留提示词要求与回复校验。Anthropic 使用统一 JSON 提示词，不发送 OpenAI 的格式参数。顾问使用模型默认采样参数，不沿用点评的温度和惩罚参数；DeepSeek 的关闭思考参数仅发送到 `api.deepseek.com`。

顾问按供应商协议读取正文，支持字符串和文本块，不把思考块当作回复。完整 JSON 对象和完整 JSON 代码围栏可解析为工具协议。任务使用 `taskState` 明确区分继续、完成、受阻和需要玩家输入；继续必须携带工具，等待施工必须调用 `wait_work`。空工具列表和“稍后继续”不再隐式表示完成，纯文字、缺少结束状态、截断或格式损坏会反馈给顾问修正；不从说明文字中提取指令。不同模型遵循工具协议的能力不同，关闭接口 JSON 约束不保证模型一定生成可执行方案；操作遵循玩家当前的手动或全自动审批设置。

布局审批会重新检查实际放置条件，普通家具上方屋顶施工不会单独使方案失效；批量操作只执行审批时确定的目标。已满足的屋顶区域设置会跳过，拆屋顶指令完整调用原版收尾逻辑。地图查询区分实际屋顶和建造/拆除屋顶区域；诊断分别返回已盖、未盖和待建屋顶数量。建造定义提供兼容材料示例、朝向要求和框架收银台/货柜用途，避免把原版储物架当作售货柜。墙和地板等无朝向选择的项目默认方向为 0，可旋转家具仍需明确方向；围墙必须拆成边段并为门留位。

顾问策略按“保留任务范围、查询资格和占地、分批执行、等待实际结果、验证营业条件”推进。地图查询保留蓝图和框架，冲突反馈列出真实对象编号及取消/拆除方式；定义提供各朝向的锚点占地偏移。货柜查询返回普通/专业类型、支持的操作、允许分类 ID、配置总量，物品查询显示禁用状态；`unique_sources` 按专业货柜返回可上架来源和具体拒绝原因。一次准备可反馈多项参数问题，整批合法后才进入审批。

`wait_work` 指定 `mapId+shopId` 时观察店铺已配置的普通库存目标和专业货柜待搬运来源，避免把施工待办清空当成补货完成；矩形模式仍只观察清理/施工。长对话建立新上下文段时，额外保留最近玩家需求与最近一次标记原文，避免连续工具回复挤掉原始范围。策略与工具目录使用稳定提示前缀，查询结果继续分页追加。

普通货柜可通过 `shelf_goods` 查询当前分类中真正允许配置的商品、单品目标上限和地面已解禁货源量；分类匹配与品质/材质硬限制分别检查。连续分配不同员工到同一岗位不会相互作废，岗位上限和个人资格仍会复查。禁止/解禁操作遇到已满足状态会跳过，重叠矩形中的相同目标在审批前去重。模型省略未使用的工具数组按空数组处理，任务状态和操作必填参数仍须完整。

顾问提示词保持稳定前缀，历史按顺序追加，查询分页发送。Anthropic 使用前缀缓存，OpenAI 兼容接口按供应商能力自动缓存；界面展示实际返回的输入、输出、缓存命中和缓存写入 token，未报告字段显示未知。开始下一条玩家消息时，较长上下文会建立新段并保留最近摘录，界面另行提示。历史随存档保存，最多保留 500 条聊天和 300 条过程记录，界面缓存排版高度且只绘制可见消息。“清空对话”取消任务并清除历史、模型上下文和待批准计划；关闭经营窗口也会停止当前任务。待批准和执行中的权限不会随存档恢复。

账目总览中的经营 K 线展示累计账面利润的每日开、高、低、收，下方柱形表示每日实收。日内极值逐笔记录并独立保存，不依赖保留账单数量。记录前的历史不补造；开始采集当天若已有成交，会标明部分记录。账面利润只扣账单中已登记的成本，允许负值，不代表包含工资、建筑等全部开支的净利润。

LLM 继续使用 OpenAI 兼容 Chat Completions 或 Anthropic Messages 接口。设置中的“测试请求”直接验证短文本生成，不再依赖顾客点评 JSON；HTTP 错误和空响应会显示具体原因。Anthropic 使用默认采样参数，官方 OpenAI 的输出限额使用 `max_completion_tokens`，其他兼容服务沿用 `max_tokens`。
